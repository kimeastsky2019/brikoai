# 지식 데이터베이스 구축 (kb)

> 문서를 **글·표·그림·엑셀** 네 채널로 분해하고, **업종별**로 분류해 적재한다.
> 적재 전에 **개인정보보호법·인공지능 기본법** 준수를 결정론적 규칙으로 검토한다.

LLMWiki 온톨로지의 원칙을 문서 지식베이스에 이식한 모듈이다.
핵심은 하나다 — **LLM 은 그래프를 채우고, 판정은 그래프 위의 룰이 한다.**

---

## 왜 이 모듈이 필요했나

기존 `app._extract_text()` 는 PDF 를 PyPDF2 로 통짜 텍스트로 만들어 `.txt` 로 올린다.
에너지진단 보고서 32면에 실제로 돌려 보면:

| | 결과 |
|---|---|
| 표 데이터 행 | 95개 |
| **행 구조(셀 순서·인접)가 보존된 행** | **21개 (22%)** |
| 구조가 깨진 행 | 74개 (78%) |

숫자 자체는 텍스트 스트림 어딘가에 남는다. 사라지는 것은 **"어느 행 어느 열의
값인가"** 다. `18대 | 22kW | 25.7kW | 7,200h | 80% | 2,664,576kWh` 가
의미를 잃는다. 에너지진단 보고서는 수치가 전부 표에 있으므로, 이 상태로는
RAG 가 문서의 절반만 검색하는 셈이 된다.

그래서 채널을 나눈다.

| 채널 | 무엇 | 앵커 | 쓰임 |
|---|---|---|---|
| `text` | 문단·서술 | page | 문제점·개선방안 검색 |
| `table` | 셀 그리드 | page + table_idx + (row,col) | **모든 수치의 출처** |
| `image` | 사진·도면·차트·로고 | page + image_idx | 증적, 명판 OCR(v0.2) |
| `excel` | 표 전체를 시트로 | sheet = p{page}_t{idx} | 감리 제출, 재계산 |

표는 **표 단위로 통째 청킹**한다. 문장처럼 자르면 행-열 관계가 다시 깨진다.

## 파이프라인

게이트를 건너뛰는 경로가 없다. 우회로를 만들면 언젠가 그 경로로 나간다.

```
PDF ─▶ 4채널 파싱 ─▶ 업종 분류 ─▶ 필수지표 커버리지
                                  │
                                  ▼
                         규제 준수 검토 (개인정보/AI기본법)
                                  │
                    blocker 있으면 ─┴─▶ 중단. 업로드 안 함
                                  │
                                  ▼
                         비식별 처리 + 마스킹 검산
                                  │
                                  ▼
                  업종 컬렉션(ediag__waste 등)에 채널별 적재
                                  │
                                  ▼
                            온톨로지 그래프
```

## 업종이 분류 축인 이유

`taxonomy.py` 의 업종 12종은 **닫힌 집합**이다. 여기 없는 업종은 그래프에
나올 수 없고, 새 업종이 필요하면 먼저 이 파일을 고쳐야 한다.

업종을 자유 문자열로 두면 같은 보고서가 업로드마다 다른 라벨을 받고,
그 순간 업종별 필터와 업종별 학습이 전부 무의미해진다.

각 업종은 프로파일을 가진다.

```python
SectorProfile(
    code="waste", name="폐기물처리·자원순환", ksic="E38",
    required_metrics=("annual_electricity_kwh", "moisture_stage", ...),
    unit_basis="처리량 1톤당",          # ← 업종마다 원단위 분모가 다르다
    key_equipment=("건조기", "보일러", "송풍기", ...),
)
```

`required_metrics` 가 이 모듈의 실질이다. **업종을 알면 무엇이 빠졌는지를
결정론적으로 물을 수 있다.** 커버리지 갭 탐지가 여기서 나온다.

`unit_basis` 때문에 업종을 섞으면 안 된다 — 건물은 ㎡당, 폐기물처리는 처리톤당이라
벤치마크가 호환되지 않는다.

### 분류는 규칙이 한다

LLM 에게 분류를 묻지 않는다.

1. 어휘 규칙으로 점수 (등장 횟수의 제곱근 — 한 단어 100번보다 10종 1번이 이겨야 한다)
2. 1·2위 격차가 25% 이상이면 확정
3. 애매하면 확정하지 않고 `needs_review=True` 로 사람에게 넘김

정밀도 우선이다. 잘못 분류된 문서는 영영 엉뚱한 컬렉션에서 검색된다.

## 규제 준수 검토

### 개인정보보호법 — 이 시스템의 구조적 쟁점

문서를 xAI(미국) Collections 로 업로드하는 순간, 문서에 개인정보가 있으면
그것은 **국외 이전**이다 (제28조의8).

실제 진단보고서 1건을 검사하면:

```
탐지 14건 — 사업자등록번호 1, 이메일 2, 전화번호 4, 상세주소 3, 성명 3(대표자·담당자·진단수행자)
판정: 차단 | 업로드 허용: False
```

에너지진단 보고서에는 **거의 항상** 담당자 성명과 연락처가 있다. 따라서
`upload_allowed_raw` 는 거의 항상 `False` 이고, 실제 적재 경로는 비식별 처리를
반드시 거친다.

마스킹은 값을 지우지 않고 **종류를 남긴 토큰**으로 바꾼다.

```
담 당 자 : 허 만 수  (063)635-8991  vitech1200@naver.com
  ↓
담당자: [성명] [전화번호] [이메일 주소]
```

`[전화번호]` 가 남아야 "여기에 연락처가 있었다" 는 사실이 검색·감리에서 보존된다.
그리고 마스킹 결과를 **다시 탐지기에 넣어 검산한다** (`verify_masking`).
게이트를 믿지 않고 검산한다 — 잔존이 있으면 적재를 막는다.

한글 문서의 자간 조판(`허 만 수`)을 견디지 못하면 탐지 자체가 무의미하므로,
직위·성명 양쪽 모두 공백을 허용하는 패턴을 쓴다.

오탐도 관리한다. 폐기물 분류코드 `51-38-01` 은 계좌번호가 아니다 —
계좌번호는 앞쪽에 금융 어휘가 있을 때만 인정한다. 준수 도구에서 오탐은 비싸다.

### 인공지능 기본법 (시행 2026.1.22)

| 조항 | 점검 | 본 시스템 |
|---|---|---|
| 제31조제1항 | 생성형 AI 서비스 사전 고지 | 화면 상단 상시 고지 |
| 제31조제2항 | 생성물 표시 | 산출물 하단 고정 표기 |
| 제34조 | 고영향 사업자 의무(인적 감독 등) | 확정 단계 자격자 서명 |
| 제2조제4호 | **고영향 해당 여부** | **판단 유보** — 룰이 확정하지 않음 |
| 제32조 | 안전성 확보 의무 | 비해당 추정 (응용 서비스) |

고영향 해당성은 정성 판단이라 룰이 답할 수 있는 질문이 아니다.
판단에 필요한 사실만 모아 사람에게 넘긴다.

**모든 `Finding` 의 `resolution` 은 비어 있다.** 판정은 룰이, 확정은 사람이 한다.

## API

```
GET  /kb/health                 상태 · 온톨로지 버전 · 채널 목록
GET  /kb/sectors                업종 닫힌 집합 (프론트 드롭다운의 유일한 출처)
GET  /kb/sectors/{code}         업종 프로파일 · 필수지표 · 컬렉션명
POST /kb/analyze                PDF → 4채널 + 분류 + 규제검토 + 온톨로지 (업로드 안 함)
POST /kb/compliance/review      텍스트 규제 검토
POST /kb/compliance/mask        비식별 처리 + 검산
POST /kb/graph/ttl              온톨로지 → TTL (Fuseki/SPARQL)
```

`app.py` 에는 한 줄로 붙는다. `kb` 의존성이 없으면 본체는 그대로 동작한다.

```python
from kb.router import router as kb_router
app.include_router(kb_router)
```

## 온톨로지

`ontology.build_graph()` 는 LLMWiki `--graph` 와 **같은 JSON 형식**을 낸다.
노드/엣지 목록이라 Neo4j·Memgraph 적재, RDF 변환, Fuseki 업로드가 모두
이 하나에서 출발한다.

### ★ 단일 실패 지점 — ID 에 좌표를 넣지 마라

규제 지식그래프가 "조문 번호를 ID 로 쓰면 개정 때 전부 깨진다" 를 단일 실패
지점으로 지목한 것과 **같은 함정**이 여기 있다.

PDF 파서를 고치면 셀 병합·회전 도면 해석이 달라져 bbox 가 밀린다. 좌표를 ID 로
쓴 그래프는 그 순간 **전부** 끊긴다. 초기에 놓치면 파서를 한 번도 개선할 수 없다.

그래서 ID 는 의미 기반이고, 좌표는 `EvidenceSpan` 의 속성으로만 산다.
`test_node_ids_contain_no_coordinates` 가 이 결정을 지킨다 — 성능 테스트가 아니라
설계 결정을 지키는 테스트다.

### 근거 등급 4단

PDF 에는 `static` 이 존재할 수 없다. 출처가 아니라 **근거 강도**를 기록한다.

| derivation | 뜻 | 예 |
|---|---|---|
| `measured` | 현장 계측기 실측 | 25.7 kW |
| `documented` | 청구서·명판·계약·법정계수 | 1,897원/kg |
| `assumed` | 가정·설계치·카탈로그 | 부하율 60% |
| `computed` | 위 셋에서 기계 계산 | 3,989,376 kWh |

감리에서 "어디까지 믿을 수 있나" 를 물으면 **`assumed` 만 검토 대상**이라고
답할 수 있다.

### 수치 추출 규칙

단위가 **숫자에 붙어 있을 때만** 양으로 인정한다. 셀 전체에서 단위를 따로 찾으면
`남원시` 의 `원` 을 화폐로, `2015년 9월` 의 `년` 을 기간으로 읽는다.
셀이 순수 숫자면 헤더의 단위를 빌려 온다 — `용량(kW)` 아래 `22` 가 진단서에서
가장 흔한 표기다.

## 알려진 한계

| 한계 | 영향 | 계획 |
|---|---|---|
| 격자선 없는 표를 놓친다 | 일부 표 누락 (경고는 남긴다) | v0.2 좌표 클러스터링 |
| 사진 속 명판 값을 못 읽는다 | 설비 제원이 그래프에 안 들어옴 | v0.2 명판 OCR |
| 스캔본 PDF 미지원 | 텍스트 레이어 없으면 빈 결과 | v0.2 OCR |
| 계산 체인(`computedFrom`)을 아직 안 만든다 | 산술 검산 룰이 못 돈다 | v0.2 — 여기가 가장 큰 미완 |
| 물질수지(함수율) 미표현 | 건조 열량 이론 검증 불가 | v0.2 |
| 업종 분류가 어휘 규칙뿐 | 신조어·이형 표기에 약함 | 오분류를 테스트로 추가하며 확장 |

**계산 체인이 v0.2 의 핵심이다.** 지금은 표에서 값을 뽑아 노드로 올리는 데까지고,
값들 사이의 수식(`연간사용량 = 정격 × 시간 × 부하율`)은 아직 그래프에 없다.
그게 들어와야 부하율 이중 적용이나 용량 부족 같은 산술 위반을 룰이 잡는다.
